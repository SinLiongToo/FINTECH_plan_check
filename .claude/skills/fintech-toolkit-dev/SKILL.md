# FinTech Toolkit — dev workflow

Static multi-page site, no build step, no framework. Pages:
`index.html`, `tools/{stock-drop,rebalance,retirement,loan,rules}/index.html`.
All pages load `assets/shared.css` + `assets/shared.js` for the shared nav,
dark/light theme toggle, and "← 返回總覽" back button. Each page sets
`window.FTK_ROOT` (relative path back to repo root) and `window.FTK_PAGE`
(nav-highlight key) in a small inline `<script>` before loading
`shared.js` — copy that pattern exactly when adding a new page.

Deployed via GitHub Pages from the `master` branch of
https://github.com/SinLiongToo/FINTECH_plan_check, live at
https://sinliongtoo.github.io/FINTECH_plan_check/. GitHub account:
**SinLiongToo** (already the account `gh` is authenticated as — confirmed
with the user once, don't re-ask).

## Before touching anything: sync with the bot

`.github/workflows/daily_stock_update.yml` commits directly to `master`
on its own schedule (weekdays, TW + US market close) and whenever
manually triggered. **Assume master has moved since you last pulled.**
Before committing:

```bash
git status --short              # see what's actually changed
git stash                       # if you have local edits and need to pull first
git pull --rebase origin master
git stash pop
```

If `git push` is rejected with "fetch first" / "non-fast-forward", that's
this — just `git pull --rebase origin master` (it cleanly rebases on top
of the bot's commit almost every time) and push again.

## Local testing loop

Every non-trivial change gets verified with a real headless browser, not
just "the file saved without errors" — several real bugs in this repo
were only caught this way (see Gotchas below).

```bash
# 1. Serve the repo root (background)
python -m http.server 8931 > /tmp/httpserver.log 2>&1 &

# 2. One-time per machine: install this skill's dev dependency (playwright)
(cd .claude/skills/fintech-toolkit-dev && npm install)

# 3. Full-site regression (nav renders, theme toggle works, no unexpected console errors)
node .claude/skills/fintech-toolkit-dev/verify.mjs
#    or against the live site directly:
node .claude/skills/fintech-toolkit-dev/verify.mjs https://sinliongtoo.github.io/FINTECH_plan_check

# 4. Stop the local server when done
pkill -f "http.server 8931"
```

For anything beyond the generic regression check — testing a specific
interaction, checking a specific element's text, comparing dark vs light,
comparing desktop vs a 375px mobile viewport — write a one-off Playwright
script inline with `node -e "..."` (see git history / prior sessions for
many examples: click a button, `waitForTimeout`, read `textContent()`,
`page.screenshot({path:...})`, then read the PNG back with the Read tool
to actually look at it). Always check **both** themes and **both**
viewport sizes (1280px desktop, 375px mobile) for anything touching
layout or color.

**Known-benign console errors** (do not chase these, they're expected):
- `rebalance`: 404 on `/api/fx` — probing for a local dev server that
  doesn't exist here; falls through to a working fallback.
- `stock-drop`: `net::ERR_CONNECTION_REFUSED` to `localhost:8765` — same
  pattern, probing for `server.py`, falls through to the static data
  pipeline.

## The stock data pipeline (`data/stock_data.json`)

`fetch_stock_data.py` (local, needs `pip install -r requirements.txt`)
pulls weekly price history + a fresher daily quote via `yfinance` for the
~55 tickers in its `TICKER_MAP`, and writes `data/stock_data.json`. Same
file is regenerated by `.github/workflows/daily_stock_update.yml` in CI.

```bash
# Fetch one ticker (fast, for testing a change to the script)
python fetch_stock_data.py --ticker aapl

# Fetch everything (slow, ~1-2 min, only when you actually need the full file)
python fetch_stock_data.py --all

# Trigger the real workflow in CI and wait for it
gh workflow run "Daily Stock Data Update" --repo SinLiongToo/FINTECH_plan_check
# copy the run URL/ID it prints, then:
gh run view <RUN_ID> --repo SinLiongToo/FINTECH_plan_check --json status,conclusion --jq '{status,conclusion}'
# (poll every ~8-10s until status is "completed"; use run_in_background + an
# until-loop rather than a foreground sleep)

# See recent runs / confirm the schedule is actually firing
gh run list --workflow="Daily Stock Data Update" --repo SinLiongToo/FINTECH_plan_check --limit 10
```

If a run says "success" but the data looks unchanged, check its log for
`No stock data changes; skipping commit.` — that means the fetch worked
but produced byte-identical output (very common: Yahoo just hasn't
published anything new yet). To check directly whether Yahoo has fresher
data available *right now* for a given symbol (bypassing the whole
pipeline), query it locally:

```bash
python -c "
import yfinance as yf
print(yf.Ticker('VT').history(period='10d', interval='1d', auto_adjust=True)[['Close']].tail(8))
"
```

A `NaN` row for the most recent date means Yahoo hasn't published that
day/week yet — not a bug in this repo. It has consistently resolved
itself within 1-2 days in past occurrences.

## Verifying a deploy actually went live

GitHub Pages rebuilds asynchronously after a push (typically 30-90s).
Don't just push and declare done — poll for the actual content:

```bash
until curl -s https://sinliongtoo.github.io/FINTECH_plan_check/<path> | grep -q '<marker-string-unique-to-your-change>'; do sleep 5; done
```

Run this via `run_in_background: true` (it can take a minute or two) and
report back once it resolves — don't sit in a foreground sleep loop.

## Gotchas already hit once — don't repeat them

- **Never write `*/` inside a `/* ... */` block comment**, even as part of
  a glob-like path in prose (e.g. `tools/*/index.html`). It silently
  closes the comment early and turns the rest of the script into a syntax
  error with no obvious symptom other than "the nav doesn't render." If a
  page's shared nav/theme button mysteriously isn't appearing, run
  `node --check <file>` won't work directly on an HTML file — extract the
  script or just grep the file for `*/` occurrences inside comments.
- **Don't use `date.toISOString()` to format a date that was parsed from a
  plain `"YYYY-MM-DDT00:00:00"` string.** It converts to UTC first and can
  shift the displayed date by one day depending on the viewer's timezone.
  Use local calendar getters (`getFullYear()`/`getMonth()`/`getDate()`)
  instead — see `fmtLocalDate()` in `tools/stock-drop/index.html`.
- **A page-level "auto fetch" button that only triggers on click** means
  the *default* view still shows stale/synthetic fallback data until the
  user acts — this reads as "the pipeline isn't working" even when it is.
  Prefer hydrating from the live data source in the background on page
  load (see `hydrateAllStocks()` in `tools/stock-drop/index.html`), with
  the button as an explicit manual refresh, not the only path to fresh
  data.
- **A public CORS proxy (AllOrigins etc.) is not reliable enough to be a
  primary data path** — confirmed in production: identical-looking
  requests in the same batch, some succeed, some `net::ERR_FAILED`, with
  no user-visible error either way. Prefer a same-origin static JSON file
  (this repo's `data/stock_data.json` pattern) and only fall back to a
  public proxy for things outside that file's coverage.
- **A horizontally-scrollable row with `scrollbar-width:none` and no other
  affordance is not discoverable.** Don't rely on a fade/gradient hint
  alone (users reported it "still not obvious" and "can't scroll back")
  — add real prev/next buttons that call `scrollBy()`.

## Design system quick reference

- `assets/shared.css` defines `--ftk-*` custom properties (bg, bg-elev,
  border, text, text-dim, accent, accent-2) under `:root` (dark) and
  `:root[data-theme="light"]`. A brand-new page (like `tools/rules/`) can
  be built entirely on these tokens and gets theme support for free.
- The four migrated tools (stock-drop, rebalance, retirement, loan) each
  have their *own* pre-existing color system instead (either their own
  CSS custom properties, or — Retirement only — raw Tailwind utility
  classes). Their light-mode support was added by overriding those
  existing systems under `html[data-theme="light"] { ... }` (or, for
  Retirement's Tailwind classes, `html[data-theme="light"] .the-class {
  ... !important }` per class actually used) — not by migrating them onto
  `--ftk-*`. Follow whichever pattern a given tool already uses.
- Git identity for automated commits is `github-actions[bot]`; your own
  commits push as whatever `gh`/`git` is locally authenticated as
  (SinLiongToo).
